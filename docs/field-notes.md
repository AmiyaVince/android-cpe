# 实测方法论

这是把一个真实项目跑通时留下的判断依据。数字来自一台具体设备，**结论比数字更值得复用**。

---

## 一、信号选点：别信"信号好"

### 判据

| 指标 | 可用 | 偏弱 | 不可用 |
|---|---|---|---|
| 制式 | NR_SA / NR_NSA | LTE | 无服务 |
| SS-RSRP | ≥ −95 dBm | −95 ~ −110 | < −110 |
| SS-SINR | ≥ 10 dB | 0 ~ 10 | < 0 |
| SS-RSRQ | ≥ −15 dB | −15 ~ −20 | < −20 |

**但判据必须包含制式和频段。** 实测过两个位置：

| 位置 | 制式 | 频段 | RSRP | SINR | 结论 |
|---|---|---|---|---|---|
| A | NR_SA | n78 | −103 | 14 | 弱覆盖但无干扰，可用 |
| B | LTE | B8 (900M) | −81 | — | RSRP 好 22 dB，但带宽潜力差一个量级 |
| C | NR_SA | n78 | −108 | 3 | 同基站，干扰重，最差 |

位置 B 的 RSRP "看起来"最好，实际是最差的选择之一。**最终只能用速率定案。**

### 采样方法

```bash
# 每次 6 个样本，间隔 5 秒
adb shell su -c 'sh tools/cpe_signal.sh'
```

要求 10/10 完全一致才算稳定驻留。制式重选有粘滞，单次快照会骗人。

### 经验修正

- "靠窗信号好" **必须加方向条件**——只有朝基站那扇窗才成立，背向的窗可能连 NR 都收不到
- **n78（3.4 GHz）对遮挡极敏感**，机箱后、金属架后直接消失
- 同一基站下换个房间，SINR 可能掉 10 dB 以上（额外衰减 + 额外干扰）

## 二、热测试：不加散热器能不能稳住

### 测点

| 类别 | 节点 | 为什么看它 |
|---|---|---|
| 电芯 | `battery` | 鼓包风险的直接指标 |
| 外壳 | `shell_back` / `shell_front` / `skin-msm-therm` | 手感与机内积热 |
| CPU | `cpu-0-0` / `cpu-1-0` / `cpu-1-3` / `cpu-1-7` | 主发热源 |
| GPU / DDR | `gpuss-0` / `ddr` | 次要热源 |
| 基带 / RF | `mdmss-0` / `pa` / `sdr*-pa` | 5G 连续收发的热，CPE 特有 |
| 降频证据 | 8 核 `scaling_cur_freq` | 掉到远低于 `cpuinfo_max_freq` 即热限频 |
| 负载 | `eth0` 收发字节、`/proc/loadavg` | 温度必须和流量对得上 |

### 判据

| 指标 | 正常 | 偏热 | 危险 |
|---|---|---|---|
| 电芯 | ≤ 35 ℃ | 35 ~ 45 | **> 45** |
| 外壳背面 | ≤ 40 ℃ | 40 ~ 45 | **> 45**（烫手） |
| CPU 大核 | ≤ 60 ℃ | 60 ~ 75 | **> 75**（多半已降频） |
| 基带 / PA | ≤ 60 ℃ | 60 ~ 70 | > 70 |

**降频判定**：大核 `scaling_cur_freq` 长时间 < `cpuinfo_max_freq` 的 60 %，且伴随高温。

### 节奏

- 前 1 小时：5 分钟一次，抓升温曲线
- 之后：15 分钟一次，看稳态与波动
- tag 用 `no_fan` / `with_fan`，各一个 CSV

```bash
./thermal_log.sh no_fan     # 采一次，追加到 no_fan.csv
```

## 三、旁路供电：电池到底有没有在工作

满电长期插电是鼓包的高危工况。限充到 45~50 % 后，需要确认电池是否真的被隔离。

### 唯一可信的三个判据

```
电芯电压（voltage_now）   → 纹丝不动
电池电流（current_now）   → 0
内核电量计（ibat / charge_counter）→ 0 变化
```

同时 `usb/current_now` 非零 —— 说明充电器在直供主板。

### 会骗人的指标

- 状态栏的充电图标
- `status` 字段（可能仍显示 Charging）
- `capacity`（可能在 50 % 停住不动，看起来像"卡住了"）

实测稳定状态：电芯 3.924 V、`current_now=0`、`ibat=0`、温度 29.3 ℃、`usb/current_now=375 mA`。

### 不要依赖的东西

- **设备树里的 bypass 属性**：这台机器没有，属于更新平台才有的方案
- **`input_current_limit=0` 放电法**：见 `discharge.sh`，带三重熔断（目标电量 / 下限 / 超时），但只适合一次性把电量降到 50 %，不适合长期

## 四、验证"流量真的走手机"

不要看 `ip route`，要看 **traceroute 第一跳**。

```
tracert 223.5.5.5
  1    <1 ms   10.193.51.214     ← 手机（共享网关）
  2     *       *               ← CGNAT 不回 TTL 超时，正常
  3    20 ms   172.21.2.1
```

同时确认：

- 客户端拿到的网关 = 手机的共享地址
- `curl --noproxy '*' --interface <客户端IP> https://www.baidu.com` 返回 200
- 手机侧 `dumpsys ethernet | grep "Tethering interface mode: 2"`

### 吞吐对照

实测有线 5.25 MB/s ≈ 42 Mbps，同源走 WiFi 热点 5.23 MB/s。

**两者一致说明瓶颈不在网线链路，而在 5G 上行或源站。** 这个对照比单测有线有意义得多。

## 五、备份（必须做在动手之前）

本仓库**不分发任何引导分区镜像**。动手前自行备份：

```bash
# 只读块设备，不写任何分区
adb shell su -c 'dd if=/dev/block/by-name/boot_b of=/data/local/tmp/boot_b.img bs=4096'
adb pull /data/local/tmp/boot_b.img .
sha256sum boot_b.img
```

需要备份的至少包括：`boot`、`vendor_boot`、`dtbo`、`vbmeta`（以及 `vbmeta_system` / `vbmeta_vendor`）。

恢复时先确认槽位：

```bash
fastboot getvar current-slot
```

**不要盲目刷入另一个槽位。**

## 六、本仓库刻意没有收录的东西

| 内容 | 原因 |
|---|---|
| 引导分区镜像（~800 MB） | 设备专属，且可能含个人信息 |
| 第三方 APK（测速、自动化工具） | 无再分发授权 |
| Android SDK / ecj / d8 | 许可限制，改为在 `build.sh` 里要求你自备 |
| 电信光猫的登录脚本 | 含 ISP 与设备专属凭据，且只对特定固件有效 |
| 游戏自动化脚本 | 与 CPE 无关，另属一个项目 |

光猫那部分的**方法**（关 DHCP、原样回填其他 LAN 字段、显式绑定源地址管理）记在 [pitfalls.md](pitfalls.md) 第 6 节。
